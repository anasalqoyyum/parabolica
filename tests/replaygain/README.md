# ReplayGain reference fixtures

Run `uv run python tests/replaygain/generate.py` to regenerate the FLAC fixtures and `references.tsv`. The generator requires FFmpeg 8.0.1, curl, tar and a C compiler. It verifies the SHA-256 of libebur128 1.2.6 before compiling the independent C runner. Application tests compare the Rust analyzer and Symphonia decoder against these C/FFmpeg measurements.

Signals, generated fixtures and the reference runner are CC0-1.0. They contain synthetic tones, envelopes and silence. Loudness/gain tolerance is 0.1 dB. Linear peak tolerances are 1e-10 for sample peak and 1e-5 for true peak. See [the implementation evidence](../../docs/implementation/replaygain-analysis.md) for measurement, grouping and validity rules.

## foobar2000 comparison

[`foobar2000.tsv`](foobar2000.tsv) records a native Windows comparison on 2026-11-15. It includes all nine tracks, all nine as one album, and the mixed-rate album consisting of `loud-44100`, `quiet-96000` and `gated-48000`. Both peak modes used the same membership and -18 LUFS reference. `unavailable` means no finite gated gain, including silence and the 190 ms fixture.

The reference is foobar2000 2.26.2 x64, downloaded from [the official package URL](https://www.foobar2000.org/downloads/foobar2000-x64_v2.26.2.exe), SHA-256 `ffa739f87d9c374cb030426a2ab4bfb37959d0dbb892fdc742654c14d127f795`. Its Authenticode signature was Valid, signed by Illustrate Ltd. The package was extracted with 7-Zip into a disposable directory with `portable_mode_enabled`; no installer ran. UI Automation drove its built-in ReplayGain scanner. Settings were ITU-R BS.1770, HD downsampling off, algorithm tags on and quiet mode off. For true peak, the selected resampler was ARDFTSRC, target 192000 Hz, quality High, with no excluded rates. Playback gain/preamp settings do not participate in the scan.

To repeat the comparison, copy the pinned fixtures into disposable folders, load each group into a fresh playlist, select all and choose ReplayGain > Scan as a single album. Run with True peak scan off, then on with the settings above. Read the four `REPLAYGAIN_*` fields from those copies after Update File Tags. The recorded foobar2000 gains retain its tag precision of 0.01 dB and peaks retain six decimals. Original fixtures must remain untouched. The TSV is captured evidence, separate from `generate.py` output; rerunning that generator does not regenerate foobar2000 measurements.

The app columns come from the current Windows binary's persisted complete measurements and album results at `e969b2692d053dbbcfd29786d220f5043e0605df`. The sample-peak mixed-rate album row was reaggregated from those persisted block distributions with the documented absolute and relative gates; its true-peak counterpart was scanned through the app. The app columns retain 12 decimals for review; analysis and storage used unrounded f64 values. Run `cargo test -p parabolica-desktop --locked pinned_fixtures_match_independent_c_libebur128` for the existing live analyzer/decoder comparison against `references.tsv`.

### Loudness and gain

Every finite non-mono track differs by at most 0.004892 dB. The mixed-rate album differs by 0.004276 dB. These pass the 0.1 dB loudness/gain tolerance. Both applications report unavailable gain for silence and sub-400 ms audio. Foobar2000 sample peaks agree within 0.0000005 linear amplitude, its six-decimal tag rounding. The stricter 1e-10 sample-peak tolerance remains applicable to the unrounded independent C reference.

Foobar2000's mono playback convention differs from the app's positioned-channel BS.1770 measurement. The mono track is -10.04 dB in foobar2000 versus -7.033439952783 dB in the app. Duplicating the decoded mono channel into left and right before the independent libebur128 1.2.6 measurement raises loudness by `10*log10(2)`, or 3.010299956640 LU. The resulting gain is -10.043739909423 dB, within 0.003740 dB of foobar2000. This control used FFmpeg 8.0.1 with `-af 'pan=stereo|c0=c0|c1=c0'`, the pinned C source/checksum and the existing `reference.c` runner, without modifying any fixture.

The same control reproduces the all-nine album difference. Its mono-doubled gated distribution gives -5.417811321587 LUFS and -12.582188678413 dB gain, within 0.002189 dB of foobar2000's -12.58 dB. The app and original independent C reference give -5.650018475314 LUFS and -12.349981524686 dB gain. This is the expected effect of changing one member's energy before album gating. No track gains were averaged, and no production analyzer correction was made.

### True peak

The true-peak modes use different estimators. Foobar2000 scans resampled PCM with its configurable ARDFTSRC filter; the app uses libebur128's pinned interpolation and tail drain, with sample peak as a lower bound. The recorded difference is not tag-rounding noise and is not tested against the C/Rust 1e-5 tolerance. The largest difference is the abrupt 12 kHz intersample fixture, 0.899982 in foobar2000 versus 0.910772442818 in the app. The other nonzero differences are at most 0.000716 linear amplitude. Album peaks select the corresponding maximum member peak in both applications.

A native foobar2000 control on fresh copies changed the intersample estimate from 0.878147 with its automatic oversampling selection to 0.899982 with explicit 192 kHz/High ARDFTSRC; loudness and gain stayed unchanged. This isolates a resampler-dependent peak estimate. The app still matches independent C libebur128 within 1e-5, including the intersample peak and tail. We retain that estimator contract rather than substituting foobar2000's resampler. These documented convention/estimator differences are the exceptions permitted by TECH_SPEC's validation step 3, not a claim of identical foobar2000 results or end-to-end clipping protection.
