# Implementation plan

[#1 Deliver Parabolica end to end](https://github.com/anasalqoyyum/parabolica/issues/1) tracks the complete delivery. 35 issues cover the player, integration, platform builds and final acceptance. P0/P1 controls order; every listed task must finish in this delivery.

## Start here

Start [#2 Build the Rust workspace and freeze integration contracts](https://github.com/anasalqoyyum/parabolica/issues/2) and [#19 Resolve Discogs access, attribution and durable tag/artwork use](https://github.com/anasalqoyyum/parabolica/issues/19) independently. The latter can need external clarification. After #2 merges, #4 becomes available. Each subsequent task starts only after its own blockers are implemented, merged and verified.

Read [the agent workflow](AGENT_WORKFLOW.md) before assigning work. Issue status labels describe the initial scheduling snapshot; the live merged implementation determines readiness.

## Implementation evidence

## Completion rules

Each feature includes the real app entry point, backend, persistence where required, expected failures and meaningful validation. Infrastructure tasks deliver tested contracts for their consumers. Real account, hardware, data-use and platform evidence remains required; fixtures do not replace it.

YouTube access and Discogs durable data/artwork use are explicit blockers. If an external requirement cannot be met, keep the affected issue and delivery tracker open and request the concrete missing input or product decision. Windows is the primary platform; the macOS/Linux tasks are also part of this issue set. Mobile/web targets remain undefined.

Do not close the tracker until #35 proves the combined app and final installable artifacts. No task is deferred to an unnamed next milestone.

## Maintain this plan

Edit [plan.json](plan.json), then run `python3 scripts/render_issue_plan.py` from the repository root. The renderer checks cycles, symmetric pairings and pairs that contradict dependency order. Committed [issue drafts](issues/) are the publication source. After publication, [github-issues.json](github-issues.json) records the actual GitHub IDs and URLs.

If scope or dependencies change during implementation, update the source plan, regenerate the documents and synchronize the affected GitHub issues and native dependencies. Preserve completion evidence when updating issue bodies.

Check the live native GitHub blockers with `python3 scripts/sync_issue_dependencies.py`. After an authorized dependency change, `--apply` adds missing links. The script stops on unexpected links so an agent can inspect them before removal.
